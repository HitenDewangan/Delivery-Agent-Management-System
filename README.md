# Delivery Agent Management System

Full-stack admin application for managing delivery agents.

> **Status: Phase 2 (database schema + Prisma).** Agent CRUD, caching, and the dashboard UI are
> implemented in later phases. This README will be expanded to the full documentation at the end.

## Technology stack

| Layer    | Technology                                                |
| -------- | --------------------------------------------------------- |
| Frontend | Next.js (App Router), TypeScript, Tailwind CSS, shadcn/ui |
| Backend  | Node.js, Express, TypeScript, Zod                         |
| Data     | PostgreSQL + Prisma 7, Redis               |
| Tooling  | ESLint, Prettier, Docker Compose                          |

## Project structure

```
delivery-agent-management/
├── backend/            Express + TypeScript API
├── frontend/           Next.js admin dashboard
├── docker-compose.yml  PostgreSQL + Redis
├── .env.example        Docker Compose variables
└── README.md
```

## Prerequisites

- Node.js 20+ and npm
- Docker with Compose v2

## Setup

```bash
# 1. Environment files
cp .env.example .env
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env.local
# Edit .env and backend/.env so the database password matches.

# 2. Start PostgreSQL and Redis
docker compose up -d
docker compose ps          # both services should report "healthy"

# 3. Install dependencies
(cd backend && npm install)
(cd frontend && npm install)

# 4. Generate the Prisma client and apply migrations
#    (npm install already runs `prisma generate` via postinstall)
(cd backend && npm run prisma:deploy)

# 5. Run (two terminals)
cd backend  && npm run dev   # http://localhost:4000
cd frontend && npm run dev   # http://localhost:3000
```

## Database

Single table `agents` (see `backend/prisma/schema.prisma`):

| Column      | Type                                   | Notes                   |
| ----------- | -------------------------------------- | ----------------------- |
| id          | UUID, primary key                      | generated by Prisma     |
| fullName    | text, required                         |                         |
| phone       | text, required, **unique**             |                         |
| email       | text, required, **unique**             |                         |
| serviceArea | text, required, indexed                |                         |
| status      | enum `ACTIVE` / `INACTIVE`             | default `ACTIVE`, indexed |
| vehicleType | enum `BICYCLE` `MOTORCYCLE` `SCOOTER` `CAR` `VAN`, optional | |
| notes       | text, optional                         |                         |
| createdAt   | timestamp                              | default now, indexed    |
| updatedAt   | timestamp                              | maintained by Prisma    |

Migrations live in `backend/prisma/migrations`. Commands (run in `backend/`):

| Command                  | Purpose                                              |
| ------------------------ | ---------------------------------------------------- |
| `npm run prisma:migrate` | Create/apply migrations in development (`migrate dev`) |
| `npm run prisma:deploy`  | Apply existing migrations (fresh DB, CI, production) |
| `npm run prisma:generate`| Regenerate the Prisma client                         |
| `npm run prisma:studio`  | Browse data in the browser                           |

## Health check

```bash
curl http://localhost:4000/health
```

Returns `200` with `status: "ok"` when PostgreSQL and Redis are reachable. If only Redis is down it
returns `200` with `status: "degraded"` (Redis is a cache, never the source of truth). If PostgreSQL
is down it returns `503` with `status: "error"`.
